### 里程碑 1 (Phase 1)：裸机引导与内核最小系统

#### 1. 实现原理与方式
- **BIOS 加电与 MBR 读取**：x86 计算机加电后由 BIOS 自检并搜寻启动介质，将第 0 扇区（512 字节且最后两字节为 `0x55AA`）读入物理地址 `0x7C00` 并跳转执行。
- **模式跃迁（16位实模式 $\rightarrow$ 32位保护模式 $\rightarrow$ 64位长模式）**：
  1. 通过 BIOS `INT 0x13` 扩展调用将软盘/硬盘后续的内核镜像读入物理内存 `0x100000`（1MB）。
  2. 激活快速 A20 地址线（通过 I/O 端口 `0x92`）解除 1MB 寻址回环。
  3. 配置初始 GDT，将 `CR0.PE` 置 1 进入 32 位保护模式。
  4. 建立初始 4 级页表（PML4, PDPT, PD, PT），设置 `CR4.PAE = 1`，将 `MSR (0xC0000080, EFER).LME` 置 1，开启 `CR0.PG = 1` 进入 64 位长模式。
  5. 汇编远跳转（Far Jump）刷新流水线，加载 64 位 GDT 代码段，跳转到内核 C++ 入口 `kmain`。
- **无标准库控制台**：直接向 VGA 文本显存 `0xB8000` 写入字符与颜色属性字节（如 `0x0F` 表示黑底亮白字），同时将字符发送到 COM1 串口（I/O 端口 `0x3F8`）直通终端。
- **C++ 裸机运行时**：重载全局 Placement New，提供内核内存打桩。

#### 2. 工具与编译依赖
- **汇编器**：`nasm -f bin boot.S -o boot.bin`（编译 512B 纯二进制引导扇区）。
- **C++ 编译器**：`g++ -m64 -std=c++17 -ffreestanding -fno-builtin -fno-exceptions -fno-rtti -nostdlib -mno-red-zone -c main.cpp`。
- **链接器**：`ld -n -T linker.ld -o kernel.elf`；`objcopy -O binary kernel.elf kernel.bin`。
- **镜像生成器**：`dd if=/dev/zero of=simpleos.img bs=512 count=2880`，`dd if=boot.bin of=simpleos.img conv=notrunc`，`dd if=kernel.bin of=simpleos.img seek=1 conv=notrunc`。
- **仿真运行**：`qemu-system-x86_64 -drive file=simpleos.img,format=raw -serial stdio`。

#### 3. 您的任务（用户需要干什么）
1. 确认已在宿主机终端安装编译工具：

   ```bash
   sudo apt update && sudo apt install -y qemu-system-x86 nasm build-essential
   ```
2. 在工程根目录下执行编译与运行指令：
   ```bash

   ```
3. 观察 QEMU 屏幕与终端控制台是否输出彩色的 `[SimpleOS] Kernel Booted Successfully!` 启动 Banner。

### 里程碑 2 (Phase 2)：中断处理、特权级与系统调用

#### 1. 实现原理与方式
- **中断描述符表 (IDT)**：x86_64 定义了 256 个中断门（Gate Descriptor，每个 16 字节），通过 `lidt` 指令加载基地址。
- **特权级切换与 TSS 内核栈**：
  - 当 Ring 3 用户态发生中断或执行系统调用时，CPU 必须自动将栈从用户栈切换至安全的内核栈。
  - CPU 硬件自动查阅当前 TSS（Task State Segment）中的 `RSP0` 字段，将栈指针切换为 `RSP0`，并在该内核栈上自动压入 `SS, RSP, RFLAGS, CS, RIP`。
- **系统调用分发机制**：
  - 注册 `0x80` 号中断门（DPL=3，允许用户态调用）。
  - 用户程序将系统调用号存入 `rax`，参数依次放入 `rdi, rsi, rdx`，执行 `int 0x80` 陷落进入内核态。
  - 内核保存全部通用寄存器组装为 `TrapContext`，分发至 `sys_write` 与 `sys_exit`。
- **首次降权运行用户程序**：内核构造初始用户栈帧，通过 `iretq` 指令原子恢复用户态 CS（DPL=3）与 RIP，开始执行用户代码。

#### 2. 工具与依赖
- `nasm` 编译 `idt_entry.S`（汇编中断存根）；
- 宿主 `g++` 编译特权级与系统调用分发类；
- GDB 调试命令（可选）：`qemu-system-x86_64 -s -S` + `gdb kernel.elf` 检查中断现场。

#### 3. 您的任务（用户需要干什么）

2. 观察内核是否成功加载外部用户程序，用户程序是否能通过系统调用打印出 `Hello, World from User Mode!`，并在执行 `exit` 后安全将 CPU 控制权还给内核。

### 里程碑 3 (Phase 3)：物理与虚拟内存管理体系

#### 1. 实现原理与方式
- **物理内存探测与管理**：在引导阶段通过 BIOS `INT 0x15, EAX=0xE820` 获取系统物理内存拓扑结构，筛选出可用 RAM 区间。
- **伙伴系统 (Buddy Allocator，进阶加分项)**：
  - 以 4KB 页帧为最小单位，构建 order 0 到 order 10（最大连续 4MB）的空闲页块链表数组。
  - 分配时若当前 order 无空闲块，则将高阶块递归一分为二（形成伙伴）；释放时检测伙伴块是否空闲，若空闲则递归向上合并，彻底解决外部内存碎片。
- **内核小对象缓存池 (Slab / Kmalloc)**：
  - 基于伙伴系统分配大页，切分为 32B、64B、128B、256B 等固定大小的 Object 链表。
  - 接管全局 `operator new` 与 `operator delete`，实现现代 C++ 面向对象的高效动态内存管理。
- **CR3 四级页表强隔离**：
  - 维护独立的 PML4（Page Map Level 4）根页表。
  - 将用户空间（`0x0000000000400000` 起始）映射到独立分配的物理页帧上，页表项配置 `PTE_U`（用户权限）。
  - 内核态空间不分配给用户页表，用户态试图访问内核地址空间立即由 CPU 硬件抛出 14 号 Page Fault 异常，内核捕获后直接终止非法进程。

#### 2. 工具与依赖
- 编译器标准类型头文件 `<cstdint>`, `<cstddef>`（Freestanding 支持）。
- 内核内存测试套件 `mm/mem_test.cpp`。

2. 观察控制台打印的伙伴系统物理页分配、释放日志，以及动态调用 `new` 和 `delete` 的验证结果；

### 里程碑 4 (Phase 4)：多任务、上下文与抢占调度

#### 1. 实现原理与方式
- **进程控制块 (PCB)**：
  - `Process` 类包含 PID、状态机（Ready / Running / Blocked / Zombie）、独立的内核栈、`TaskContext` 寄存器结构体、独立的 `CR3` 页表地址。
- **64 位寄存器上下文切换 (`switch_to`)**：
  - 依据 System V AMD64 ABI，跨函数切换仅需保存 Callee-Saved 寄存器（`rbx, rbp, r12, r13, r14, r15, rsp`）。
  - 汇编代码将当前寄存器 push 入旧栈，将旧栈顶存入旧 PCB；从新 PCB 读取新栈顶存入 `rsp`，并 pop 出新寄存器执行 `ret`。
- **PIT 8254 可编程定时器与时钟中断**：
  - 配置主板 8254 芯片（I/O 端口 `0x40/0x43`），设置中断频率为 100Hz（每 10ms 产生一次 IRQ 0 / 32 号中断）。
- **调度策略**：
  - 基础实现：Round-Robin 时间片轮转，每 10ms 递减时间片，归零时抢占调度。
  - 进阶实现：多级反馈队列 (MLFQ)，建立 Q0 (高优/5ms)、Q1 (中优/10ms)、Q2 (低优/20ms) 三级就绪队列。

#### 2. 工具与依赖
- 内置 NASM 汇编文件 `arch/x86_64/switch.S`。
- 多任务交替测试用户程序 `apps/multitask_demo.cpp`。

#### 3. 您的任务（用户需要干什么）

2. 观察控制台输出：启动 3 个并发任务，观察各任务的输出字符是否在时钟中断驱动下交替打印输出，验证抢占调度已生效。

### 里程碑 5 (Phase 5)：并发同步与经典银行存取款仿真

#### 1. 实现原理与方式
- **硬件原子自旋锁 (`SpinLock`)**：
  - 利用 x86 总线锁前缀与原子指令 `lock cmpxchg` 或 `xchg`，实现多核/并发互斥，配合 RAII 守卫类 `LockGuard` 自动释放。
- **睡眠信号量 (`Semaphore` P-V 原语)**：
  - 维护内部阻塞等待队列 `WaitQueue` 与计数器。
  - `wait()` (P 操作)：计数器原子减 1，若 $< 0$，将进程置为 `Blocked` 状态，加入等待队列并调用调度器让渡 CPU。
  - `signal()` (V 操作)：计数器原子加 1，若 $\le 0$，从等待队列弹出一个进程唤醒至就绪队列。
- **经典银行账户存取款仿真模型 (`apps/bank_demo.cpp`)**：
  - 全局共享账户 `BankAccount`，初始本金 10000 元。
  - 派生 10 个线程，并发高频执行 1000 次存 10 元和取 10 元。
  - **对照实验设计**：
    - 无锁状态下，因汇编指令读-改-写被时钟中断抢占，最终余额出现错乱（如变成 8450 元），直观展示数据竞争漏洞。
    - 启用信号量 P-V 保护后，10 个线程严格互斥访问临界区，最终余额恒等于 10000 元，直观展示同步机制的正确性。

#### 2. 工具与依赖
- x86 原子内联汇编。
- 银行仿真业务测试代码。

#### 3. 您的任务（用户需要干什么）
1. 执行 `make run`。
2. 在控制台查看 `bank_test` 运行结果，记录无锁状态下的偏差数据与加锁状态下的平整数据（这部分直接用于撰写实验报告和答辩演示）。

#### 4. AI 负责交付的内容
- 编写 `sync/spinlock.cpp`、`sync/semaphore.cpp`、`sync/mutex.cpp`。
- 编写 `apps/bank_demo.cpp`。

### 里程碑 6 (Phase 6)：VFS 文件系统与 ELF64 加载执行

#### 1. 实现原理与方式
- **虚拟文件系统 (VFS) 抽象**：定义统一的面向对象文件接口 `VNode` 与 `FileSystem`，支持统一挂载管理。
- **内存只读文件系统 (RamFS)**：
  - 将编译期生成的用户态二进制 ELF 文件通过链接器符号或打包脚本嵌入内核只读段，系统开机后即自动挂载为根目录 `/`。
- **ELF64 二进制动态加载器 (`loader/elf.cpp`)**：
  - 解析 64 位 ELF Header 与 Program Header 表；
  - 遍历所有 `PT_LOAD` 段，依据段的虚拟地址 `p_vaddr` 与内存尺寸 `p_memsz`，在当前进程页表中分配物理页并映射，拷贝数据段并清空 BSS 段；
  - 读取入口地址 `e_entry` 写入 TrapFrame 的 RIP 寄存器。
- **交互式命令行 Shell (`user/sh.cpp`)**：
  - 通过键盘中断与串口读取用户输入，提供命令解析器，支持 `ls`, `ps`, `cat`, `bank_test`, `gui`, `reboot` 等命令。

#### 2. 工具与依赖
- 宿主 `ld` / `objcopy` 工具，将独立编译的应用程序打包进内核镜像。
- 串口输入响应支持。

### 里程碑 7 (Phase 7 - ★核心主打加分)：GUI 2D 桌面与动态系统监视器

- **VBE / Bochs 线性显存 Framebuffer 驱动**：

  - 将显存线性物理基地址（通常为 `0xE0000000` 或 `0xFD000000`）映射至内核高地址虚拟空间。
- **双缓冲无撕裂渲染管线**：
  - 在内核堆中申请与显存等大的后台缓冲区 `back_buffer`（$1024 \times 768 \times 4\text{ 字节} \approx 3.14\text{MB}$）。

- **2D 绘图引擎与字库**：
  - 纯手写 Bresenham 线段抗锯齿光栅化算法；
  - 支持实心矩形填充与 Alpha 半透明混合；

- **动态性能监视器桌面 Demo**：
  - 绘制深色磨砂质感顶栏（显示 SimpleOS Logo、运行时间、CPU 频率、内存水位）；
  - 绘制动态监控窗口，将系统的 CPU 调度负载以平滑折线波形图的形式随时间轴动态滚动更新。
