# SimpleOS 项目实施步骤文档 (完整落地指南)

---

## 1. 实施路线图与阶段规划

本项目依据操作系统内核工程规范，结合 **x86_64 原生架构** 与 **C++17/20 Freestanding** 特性，将系统演进细化为 **7 个核心实施阶段（里程碑）**。每个阶段均包含“设计目标、代码编写清单、核心技术原理、验证测试命令、进阶与加分项验收”五个维度。

```
[Phase 1: 裸机引导与内核最小系统] ────> 验证 MBR 启动、长模式跳跃、串口/VGA kprintf
               │
               ▼
[Phase 2: 中断异常、特权级与系统调用] ──> 验证 IDT 256 门、Ring0/3 隔离、sys_write/exit
               │
               ▼
[Phase 3: 物理内存与虚拟分页体系] ────> 验证 Buddy 伙伴系统、Slab/kmalloc、CR3 四级分页
               │
               ▼
[Phase 4: 多任务、上下文与抢占调度] ──> 验证 PCB 状态机、switch_to 汇编切换、PIT 时钟轮转
               │
               ▼
[Phase 5: 并发同步与银行存取款仿真] ──> 验证 SpinLock、Semaphore P-V、银行账户数据竞争/加锁对比
               │
               ▼
[Phase 6: VFS 文件系统与 ELF 加载] ────> 验证 RamFS/FAT32、ELF64 解析、用户态交互式 Shell
               │
               ▼
[Phase 7: ★核心高端加分：GUI 桌面] ────> 验证 VBE Framebuffer 1024x768、双缓冲、2D 图形与动态监控
```

## 3. 分阶段具体实施步骤

### 3.1 里程碑 1：裸机引导与内核最小系统 (Phase 1)
- **目标**：编写符合 PC 规范的 MBR 引导扇区，开启 A20 地址线并跳转至 64 位长模式，加载 C++ 内核并实现基础控制台打印。
- **实施步骤**：
  1. **编写 MBR 引导扇区 (`arch/x86_64/boot.S`)**：
     - 在 16 位实模式下通过 BIOS `INT 0x13` 扩展读取磁盘后续扇区（内核镜像）至物理地址 `0x100000`（1MB）。
     - 加载临时 32 位 GDT，置位 `CR0.PE` 跳入保护模式；
     - 构建初始 4 级页表（PML4, PDPT, PD, PT），设置 `CR4.PAE = 1`，置位 `EFER.LME`，开启长模式；
     - 设置引导扇区魔数 `0xAA55`（占满 512 字节）。
  2. **编写内核链接脚本 (`linker.ld`)**：
     - 设定内核入口为 `kernel_entry`，内核基地址为 `0x100000`（物理 1MB）或高半核 `0xFFFFFFFF80100000`。
     - 按序放置 `.text`、`.rodata`、`.data`、`.bss` 段，并导出 `_skernel`、`_ekernel` 边界符号。
  3. **搭建 C++ 裸机运行时基础设施 (`lib/cxx_runtime.cpp`)**：
     - 重载 Placement New：`void* operator new(size_t, void* ptr) noexcept { return ptr; }`。
     - 禁用标准库符号，处理纯虚函数异常桩 `__cxa_pure_virtual()`。
  4. **实现格式化打印与控制台驱动 (`kernel/kprintf.cpp` & `drivers/vga.cpp`)**：
     - 驱动 VGA 文本模式（显存物理地址 `0xB8000`，80×25 字符矩阵）；
     - 驱动 COM1 串口（I/O 端口 `0x3F8`），输出日志到宿主机控制台；
     - 纯手写实现无依赖的 `kprintf`，支持 `%d, %u, %x, %p, %s, %c` 与色彩转义码。
  5. **编写顶级 `Makefile`**：
     - 支持 `make build`（编译 boot.bin + kernel.bin，使用 `dd` 合成软盘/硬盘镜像 `simpleos.img`）；
     - 支持 `make run`（执行 `qemu-system-x86_64 -drive file=simpleos.img,format=raw -serial stdio`）。
- **验收指标**：启动 QEMU 并在 VGA 屏幕和终端中同步打印出彩色的 `[SimpleOS] Kernel Booted Successfully!` Banner。

### 3.2 里程碑 2：中断处理、特权级与系统调用 (Phase 2)
- **目标**：构建 256 门 IDT 中断描述符表，建立特权级（Ring 0 / Ring 3）隔离，实现用户态通过系统调用打印及安全退出。
- **实施步骤**：
  1. **配置 GDT 与 TSS (`arch/x86_64/gdt.cpp`)**：
     - 设置内核代码段/数据段选择子（Ring 0）、用户代码段/数据段选择子（Ring 3）；
     - 初始化 TSS（Task State Segment），配置 `RSP0`（特权级切换时的内核栈顶指针）。
  2. **初始化 IDT 与中断分发 (`arch/x86_64/idt_entry.S`, `arch/x86_64/idt.cpp`)**：
     - 编写汇编宏为 0~255 号中断生成通用入口存根（Stub）；
     - 在内核栈压入 `rax, rbx, rcx, rdx, rsi, rdi, rbp, r8~r15`，组装 `TrapContext` 结构体；
     - 分发 0~31 号异常（如除以零、非法指令、页错误 PageFault 14号）；
     - 加载 IDTR：`lidt [idtr]`。
  3. **实现系统调用核心机制 (`kernel/syscall.cpp`)**：
     - 注册 `0x80` 号软件中断门（DPL=3，允许 Ring 3 用户代码执行 `int 0x80`）；
     - 制定系统调用号：`SYS_WRITE (1)`、`SYS_EXIT (2)`、`SYS_YIELD (3)`；
     - 根据 `TrapContext.rax` 分发系统调用，参数由 `rdi, rsi, rdx` 传入，返回值写入 `TrapContext.rax`。
  4. **编写用户态基础库与测试程序 (`user/libuser.cpp`, `user/hello.cpp`)**：
     - 用户态内联汇编封装 `syscall(id, arg0, arg1, arg2)`；
     - 编写用户程序 `hello.bin`，调用 `printf("Hello from User Space!\n")` 并执行 `exit(0)`。
  5. **特权级降权切换 (`arch/x86_64/user_switch.S`)**：
     - 内核构造伪造的 Trap 栈帧（用户态 CS、SS、RSP、RFLAGS、RIP），执行 `iretq` 切换至 Ring 3 执行 `hello.bin`。
- **验收指标**：系统从内核态成功降权进入用户态执行代码，用户程序发起 `sys_write` 打印并在 `sys_exit` 后安全将控制权交还内核。

### 3.3 里程碑 3：物理与虚拟内存管理体系 (Phase 3)
- **目标**：构建伙伴系统物理内存分配器、Slab 内核小对象缓存，以及 x86_64 4级分页隔离体系。
- **实施步骤**：
  1. **物理内存探测与页帧分配 (`mm/frame.cpp`)**：
     - 读取 MBR 探测的 BIOS E820 内存图，确定物理可用内存边界；
     - 按照 4KB 页粒度建立 Bitmap / 页帧管理器。
  2. **进阶加分：伙伴系统实现 (`mm/buddy.cpp`)**：
     - 实现 Buddy System 物理页分配器，按 $2^k$ 阶合并连续物理页，根治外部碎片；
     - 提供 `alloc_pages(order)` 与 `free_pages(page, order)`。
  3. **内核堆 Slab 分配器 (`mm/slab.cpp`)**：
     - 构建 32B、64B、128B、256B、512B、1024B、2048B 固定小对象缓存池；
     - 重载全局 `operator new` / `operator delete`，实现 `kmalloc` / `kfree`。
  4. **x86_64 4级分页映射 (`mm/pagetable.cpp`)**：
     - 封装 PML4、PDPT、Page Directory、Page Table 类；
     - 实现 `map_page(vaddr, paddr, flags)` 与 `unmap_page(vaddr)`；
     - 内核虚拟空间恒等映射，用户虚拟空间隔离映射并设置 `PTE_U`（用户可访问）、`PTE_W`（可写）、`PTE_NX`（不可执行）。
- **验收指标**：动态创建/销毁 C++ 对象（`new/delete`）无内存泄漏；测试用户态非法访问内核高地址时由 CPU 触发 Page Fault 并被安全捕获。

### 3.4 里程碑 4：多任务、上下文与抢占调度 (Phase 4)
- **目标**：实现 PCB 状态管理，基于 `switch_to` 的上下文切换，以及由 PIT 时钟中断驱动的抢占式多任务调度。
- **实施步骤**：
  1. **设计进程控制块 PCB (`task/process.cpp`)**：
     - 包含 PID、进程状态（Ready, Running, Blocked, Zombie）、`TaskContext`、私有 4 级页表（CR3）、内核栈、时间片余量。
  2. **编写上下文切换汇编核心 (`arch/x86_64/switch.S`)**：
     - `switch_to(TaskContext* prev, TaskContext* next)`；
     - 保存 `prev` 的 `rbx, rbp, r12, r13, r14, r15, rsp, rip`，载入 `next` 的对应寄存器并 `ret`。
  3. **配置可编程定时器 PIT 8254 (`drivers/pit.cpp`)**：
     - 设置 PIT 振荡频率为 100Hz（每 10ms 触发一次 IRQ 0 / 32 号中断）。
  4. **调度器引擎实现 (`task/scheduler.cpp`)**：
     - 维护双向就绪队列（`ReadyQueue`）；
     - **时间片轮转 (RR)**：时钟中断递减时间片，时间片为 0 时调用 `schedule()` 调度下一个就绪进程；
     - **进阶加分：多级反馈队列 (MLFQ)**：建立 Q0 (5ms)、Q1 (10ms)、Q2 (20ms) 三级优先级队列，CPU 密集型自动降级，IO 唤醒提升至高优先级。
- **验收指标**：创建 3 个打印不同字符（'A'、'B'、'C'）的用户进程，终端输出交错规律打印，验证了分时抢占调度的有效性。

### 3.5 里程碑 5：并发同步与银行存取款仿真 (Phase 5)
- **目标**：实现自旋锁与信号量 P-V 原语，构建经典银行存取款并发测试，直观复现数据竞争与加锁一致性对比。
- **实施步骤**：
  1. **硬件原子自旋锁 (`sync/spinlock.cpp`)**：
     - 基于 x86 `lock cmpxchg` / `xchg` 指令实现原子测试与设置；
     - 配合 `SpinLockGuard`（RAII 守卫类）确保离开作用域自动解锁。
  2. **睡眠互斥锁与信号量 (`sync/semaphore.cpp`)**：
     - 维护计数器 `count` 与等待阻塞队列 `WaitQueue`；
     - `wait()` (P 操作)：计数器减 1，若 $< 0$，将当前进程置为 `Blocked` 并让渡 CPU；
     - `signal()` (V 操作)：计数器加 1，若 $\le 0$，从等待队列唤醒一个进程加入就绪队列。
  3. **编写银行存取款并发测试程序 (`apps/bank_demo.cpp`)**：
     - 定义共享账户 `BankAccount`，初始余额 10000 元；
     - 派生 10 个线程，并发循环各执行 1000 次存款 10 元和取款 10 元；
     - **模式 A（无锁测试）**：直接读写 `balance`，因为时钟中断打断并发指令，导致“丢失修改”，最终余额出现巨额偏差；
     - **模式 B（P-V 锁保护测试）**：存取款由 `Semaphore(1)` 临界区保护，执行完毕后最终余额绝对恒等于 10000 元。
- **验收指标**：在终端运行 `bank_demo`，直观输出未加锁时的错误差额与加锁后的完美账目平衡，为答辩提供决定性质检证据。

### 3.6 里程碑 6：虚拟文件系统 (VFS) 与 ELF64 加载执行 (Phase 6)
- **目标**：建立 VFS 抽象层与 RamFS/FAT32，解析 ELF64 目标可执行文件，实现可交互的用户终端 Shell。
- **实施步骤**：
  1. **构建 VFS 抽象接口 (`fs/vfs.cpp`)**：
     - 定义 `VNode`、`FileSystem`、`File` 结构，提供 `open`、`read`、`write`、`readdir`。
  2. **内嵌 RamFS 内存文件系统 (`fs/ramfs.cpp`)**：
     - 将预编译的用户程序（ELF 格式）作为只读数组直接打包进内核只读段，开箱即用。
  3. **ELF64 解析器与装载器 (`loader/elf.cpp`)**：
     - 验证 ELF Magic（`0x7F 'E' 'L' 'F'`）与 x86_64 机器号；
     - 遍历 Program Header 表，筛选 `PT_LOAD` 段；
     - 在进程页表中按段需求分配物理页并建立虚拟映射，拷贝数据并清空 BSS；
     - 提取 `e_entry` 入口地址，作为进程执行起点。
  4. **编写交互式用户终端 Shell (`user/sh.cpp`)**：
     - 提示符 `SimpleOS# `，支持接收键盘字符输入与退格修正；
     - 内置命令：`help`, `ls`, `cat`, `ps`, `bank_test`, `gui`, `reboot`。
- **验收指标**：开机后自动拉起 `sh`，在终端输入 `ls` 列出程序，输入 `bank_test` 启动并发测试，输入可执行文件名自动完成 ELF 加载运行。

### 3.7 里程碑 7：【★核心主打加分】GUI 2D 桌面与动态系统监视器 (Phase 7)
- **目标**：驱动 VBE/Bochs 线性显存 Framebuffer（1024×768×32bpp），实现双缓冲 2D 渲染引擎与实时动态监控桌面。
- **实施步骤**：
  1. **显存线性物理映射 (`drivers/vbe.cpp`)**：
     - 在引导或内核阶段配置 Bochs VBE 寄存器（端口 `0x1CE / 0x1CF`），设置分辨率 `1024×768`，色深 `32bpp`（ARGB）；
     - 将显存线性基地址映射入内核高地址，获取显存操作指针 `uint32_t* fb`。
  2. **高性能双缓冲图形管线 (`gui/canvas.cpp`)**：
     - 在堆上分配与屏幕同等大小的后台缓冲区 `back_buffer`；
     - 绘图操作全部在 `back_buffer` 进行，调用 `swap_buffer()` 时通过优化的 64 位内存拷贝刷入硬件显存，彻底消除画面撕裂与闪烁。
  3. **2D 图形与排版库 (`gui/painter.cpp`)**：
     - 点绘制与矩形填充（支持透明度 Alpha 混合）；
     - Bresenham 线段抗锯齿光栅化算法；
     - 内嵌 8×16 ASCII 点阵字库，支持任意坐标多色彩文字输出。
  4. **构建动态系统监控桌面 Demo (`gui/desktop.cpp`)**：
     - **顶层状态栏**：绘制深色半透明状态栏，左侧显示 `SimpleOS Desktop v1.0`，右侧实时显示开机运行时间（Uptime）与当前内存占用量；
     - **CPU 性能折线波形图窗口**：绘制带边框与网格背景的监视窗口，利用 Bresenham 算法随定时器滚动绘制 CPU 负载动态折线波形图；
     - **任务状态列表小部件**：实时显示当前系统的所有线程名与运行状态。
- **验收指标**：在 Shell 中输入 `gui` 或开机默认加载 GUI，QEMU 窗口瞬间呈现出绚丽、丝滑刷新、带有动态走势波形的图形桌面。

## 5. 随堂小提问（抗干扰 1分）预设问答备忘

1. **问：为什么 x86_64 特权级切换必须要配置 TSS 的 `RSP0`？**
   - *答*：当 CPU 在 Ring 3（用户态）遇到中断或执行 `int 0x80` 时，CPU 硬件自动从当前任务的 TSS 结构体中读取 `RSP0` 作为内核栈顶，并切换栈指针后再压入上下文。若未配置 `RSP0`，特权级切换将引发 Double Fault (0x08) 导致系统崩溃重启。
2. **问：上下文切换（`switch_to`）为什么不需要保存所有寄存器，只保存 Callee-Saved 寄存器？**
   - *答*：因为 `switch_to` 是以标准 C++ 函数调用的形式触发的。按照 System V AMD64 ABI 规范，调用者保存寄存器（Caller-saved，如 `rax, rcx, rdx`）已经在进入函数前被编译器自动保护了，被调用者只需要保证 `rbx, rbp, r12~r15, rsp` 在跨函数切换时保持不变即可。
3. **问：银行账户存取款仿真中，为什么不加锁必然产生账目错误？**
   - *答*：因为 `balance += amount` 在汇编层面由“读内存、算加法、写内存”三条指令构成。多线程并发时，时钟中断可能在读出旧值后、写回新值前切走 CPU，导致后执行的线程覆盖了先执行线程的写入结果，造成经典的“丢失更新”（Lost Update）数据竞争。
