# SimpleOS 项目目录结构说明

## 当前状态

当前提交只建立目录骨架，不包含内核实现、构建工具或可运行镜像。空目录中的 `.gitkeep` 只是 Git 占位文件；加入真实文件后可以删除对应的 `.gitkeep`。`build/` 由未来的构建过程创建，并由 `.gitignore` 排除。

## 目录职责

| 目录 | 职责 |
| --- | --- |
| `src/boot/` | 引导器配置和从引导环境进入内核的启动代码。具体文件取决于引导协议。 |
| `src/arch/x86_64/` | x86_64 特有的特权级、中断入口、上下文切换及底层指令封装。 |
| `src/kernel/` | 内核初始化、控制台、错误处理和系统调用等核心服务。 |
| `src/drivers/` | 串口、定时器等设备的驱动实现。 |
| `src/mm/` | 物理页帧、页表和内核堆等内存管理功能。 |
| `src/task/` | 任务和进程控制块、调度与生命周期管理。 |
| `src/sync/` | 自旋锁、信号量等同步原语。 |
| `src/fs/` | 文件和目录的组织与访问；初期可考虑简单的只读内存文件集合。 |
| `src/loader/` | 用户程序格式解析和装载，例如 ELF。 |
| `src/lib/` | 无宿主环境下供内核使用的基础工具。 |
| `include/` | 内核各模块共享的头文件，子目录与模块职责对应。 |
| `src/user/lib/` | 用户态程序使用的系统调用封装及基础运行支持。 |
| `src/user/apps/` | 独立编译的用户程序和演示程序。 |
| `tests/` | 按功能组织的测试，包括内存、调度和系统调用测试。 |
| `scripts/` | 构建镜像、运行与调试等辅助脚本。 |
| `docs/`、`steps/` | 项目设计、学习资料、阶段指南与验证记录。 |
| `TEMP/` | 已有的参考实验材料；其技术路线不等同于本项目实现。 |

## 分阶段使用

1. **最小内核**：先确定引导协议和工具链，在 `src/boot/`、`src/kernel/` 和 `src/drivers/` 中实现启动与输出。
2. **异常和系统调用**：逐步使用 `src/arch/x86_64/`、`src/kernel/` 和 `src/user/`，验证用户态与内核态的交互。
3. **内存与任务**：在 `src/mm/` 和 `src/task/` 中实现内存管理、上下文切换及调度，并添加对应测试。
4. **同步和程序加载**：根据需求实现 `src/sync/`、`src/fs/`、`src/loader/` 及用户程序，记录验证结果。

这些阶段是开发路线，不代表当前已完成。目录和模块边界可随实际设计调整；新增源码时应解释关键硬件约束、上下文切换和内存布局等不易从代码直接看出的原因。
