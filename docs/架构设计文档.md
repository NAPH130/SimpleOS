# SimpleOS 架构设计文档 (完整版)

---

## 1. 总体架构设计与设计原则

### 1.1 设计哲学与核心原则
**SimpleOS** 是一个采用纯现代 C++（Freestanding C++17/20）构建的高内聚、微模块化单体操作系统。系统原生适配当前宿主机的 **x86_64** 体系结构（AMD Ryzen 7 9700X），具备以下核心原则：
1. **指令集原生匹配与分层解耦（HAL）**：内核原生面向 **x86_64** 架构开发，硬件抽象层（HAL）将 CPU 特权指令、CR3 分页寄存器、IDT 中断描述符表、PIT/APIC 定时器及 VBE 显卡驱动严密封装，杜绝跨平台交叉编译带来的工具链依赖，上层内核逻辑纯净通用。
2. **现代 C++ 零开销抽象与 RAII**：充分利用 C++ 的构造/析构函数实现 RAII（资源获取即初始化，如 `LockGuard`、`UniquePtr`），利用强类型枚举、模板与内联函数，在保证零额外运行时开销的同时杜绝裸指针悬挂与未释放锁引发的死锁。
3. **阶梯式渐进演化与 MBR 对齐**：严格遵循课程大纲，从 16 位实模式到 64 位长模式的 **MBR Bootloader** 引导，逐步演进至 IDT 中断分发、CR3 多级分页、抢占式分时调度、P-V 互斥及文件系统，演进路线清晰无断层。
4. **主打 GUI 视觉化加分展示**：以 **GUI 2D 桌面引擎（VBE 线性 Framebuffer）** 作为核心主打高端加分项，实现高分辨率真彩色桌面、双缓冲无闪烁渲染、时钟与动态性能监视器控件，并在架构中保持 SMP 多核、安全隔离与网络栈作为备选扩展。

## 2. 引导、特权级与上下文切换架构

### 2.1 物理内存布局与 MBR 引导设计
内核原生适配 x86_64 体系，遵循标准 PC 物理内存规范与 MBR 引导标准：

```
+-------------------------------------------------------------------------+
|  0x00000000 ~ 0x00007BFF  : BIOS 中断向量表 (IVT) 与实模式数据区 (BDA)  |
+-------------------------------------------------------------------------+
|  0x00007C00 ~ 0x00007DFF  : MBR 引导扇区 (512 字节，BIOS 自动装载运行)  |
+-------------------------------------------------------------------------+
|  0x00100000 ~ _ekernel    : 1MB 以上高端内存，内核镜像 (Text, Data, BSS)|
+-------------------------------------------------------------------------+
|  _ekernel   ~ HeapEnd     : 内核动态堆空间 (Buddy System / Slab 管理)   |
+-------------------------------------------------------------------------+
|  HeapEnd    ~ MaxPhysRAM  : 物理页帧池 (Page Frame Allocator 管理)      |
+-------------------------------------------------------------------------+
|  User Space Virtual Map   : 用户程序虚拟空间 (0x000000400000 ~ 0x7FFF..) |
+-------------------------------------------------------------------------+
```
- **MBR 阶段启动流程**：BIOS 加电自检完成，将磁盘第 0 扇区（MBR 512 字节）读入物理地址 `0x7C00`；MBR 汇编开启 A20 地址线，配置初步 GDT 临时跳入 32 位保护模式，随后建立初始 4 级页表（PML4），设置 `EFER.LME = 1` 与 `CR0.PG = 1` 开启 64 位长模式（Long Mode），最后跳转至 1MB 高端内存的内核主入口 `kmain`。

### 2.2 特权级隔离与 IDT / 中断异常架构
系统严格分离 **Ring 0（内核特权态）** 与 **Ring 3（用户态）**：
1. **中断描述符表 (IDT - Interrupt Descriptor Table)**：
   - 建立 256 个中断门描述符，涵盖 0~31 号 CPU 异常（0 号除以零，14 号缺页 Page Fault 等）与 32~255 号外设中断（PIT 时钟、键盘）及系统调用（`int 0x80` 或 `syscall`）。
2. **Trap 现场保存（`TrapFrame`）**：
   - 当由用户态（Ring 3）触发中断或系统调用时，x86_64 CPU 硬件自动根据 TSS（Task State Segment）中记录的 `RSP0` 切换到当前进程的**内核栈**，并自动压入 `SS, RSP, RFLAGS, CS, RIP`。
   - 通用异常处理入口汇编宏将 15 个通用寄存器（`rax, rbx, rcx, rdx, rsi, rdi, rbp, r8~r15`）压栈，构造出强类型的 `TrapContext` 结构体，作为参数传入 C++ 分发器 `TrapDispatcher::dispatch(TrapContext* ctx)`。
3. **Trap 返回（`iretq` / `sysretq`）**：
   - 恢复全部通用寄存器，最后执行 `iretq` 指令，硬件原子恢复用户态 `CS`（Ring 3 选择子）、`RFLAGS`、`RSP` 与 `RIP`，安全降权返回用户态。

### 2.3 线程级上下文切换（`switch_to`）
进程调度切换不同于中断处理，遵循 System V AMD64 ABI 约定，仅需保存 **Callee-Saved 寄存器**（`rbx`, `rbp`, `r12`~`r15`, `rsp`），调度开销低至数个时钟周期：
```cpp
struct TaskContext {
    uint64_t rip;
    uint64_t rsp;
    uint64_t rbx;
    uint64_t rbp;
    uint64_t r12;
    uint64_t r13;
    uint64_t r14;
    uint64_t r15;
};

extern "C" void switch_to(TaskContext* current_ctx, TaskContext* next_ctx);
```

## 3. 核心子系统架构设计

### 3.1 内存管理子系统（Memory Architecture）
SimpleOS 采用阶梯式演进架构，从“可变分区连续分配”无缝升级为“多级分页强隔离”：

```
                    ┌────────────────────────┐
                    │      Physical RAM      │
                    └───────────┬────────────┘
                                │
                  ┌─────────────┴─────────────┐
                  ▼                           ▼
        ┌───────────────────┐       ┌───────────────────┐
        │   Buddy Allocator │       │   Page Frame Pool │
        │   (物理页帧管理器)│       │   (4KB 粒度页分配)│
        └─────────┬─────────┘       └─────────┬─────────┘
                  │                           │
                  ▼                           ▼
        ┌───────────────────┐       ┌───────────────────┐
        │   Slab / Kmalloc  │       │ SV39 Multi-Level  │
        │   (内核小对象池)  │       │ Page Table (MMU)  │
        └───────────────────┘       └─────────┬─────────┘
                                              │
                                              ▼
                                    ┌───────────────────┐
                                    │     MemorySet     │
                                    │ (虚拟地址空间抽象)│
                                    └───────────────────┘
```

1. **物理页帧分配器（Frame Allocator）**：
   - 采用 **伙伴系统（Buddy System）** 算法，以 4KB 页为最小粒度，向上合并成 $2^k$ 阶的大块连续物理页，从源头上解决外部内存碎片问题。
2. **内核堆分配器（Kmalloc / Slab）**：
   - 基于伙伴系统构建 Slab 分配器，预先创建 32B, 64B, 128B, 256B, 512B, 1024B, 2048B 的固定大小对象缓存池，避免频繁申请整页，重载 C++ 全局 `new` 与 `delete`。
3. **虚拟地址空间与分页保护（x86_64 4级分页 MMU）**：
   - 启用 x86_64 硬件标准 4 级页表（PML4 -> PDPT -> Page Directory -> Page Table），基地址加载至 `CR3` 控制寄存器。
   - 划分虚拟空间：低地址（`0x0000000000400000 ~ 0x00007FFFFFFFFFFF`，Canonical 低区）为用户私有空间，映射用户代码段、数据段、堆和用户栈；高地址（`0xFFFF800000000000` 以上）为内核恒等映射空间。
   - 严格配置页表标志位（PTE）：`P=1`（存在位）、`U/S=1`（用户可访问）、`R/W=0`（只读代码段）、`NX=1`（数据栈不可执行，结合 AMD EFER.NXE 开启 DEP 防御）。

### 3.2 进程与调度子系统（Task & Scheduler Architecture）
1. **进程控制块（PCB - Process Control Block）**：
   - `Process` 类封装进程生命周期核心元数据：
     - `pid_t pid`：唯一进程识别号；
     - `ProcessState state`：状态机（`Ready`, `Running`, `Blocked`, `Zombie`）；
     - `TaskContext context`：用于任务切换的上下文；
     - `TrapContext* trap_ctx`：进入内核态时保存的用户现场；
     - `uintptr_t kernel_stack_top`：进程专有内核栈顶；
     - `MemorySet memory_set`：进程私有虚拟地址空间；
     - `IntrusiveListNode link`：侵入式就绪/等待队列节点（零动态内存分配开销）；
     - `int32_t exit_code`：子进程退出码；
     - `Process* parent` 与 `KVector<Process*> children`：父子继承关系树。
2. **调度策略与算法（Scheduler Engine）**：
   - **基础算法：时间片轮转（Round-Robin, RR）**：
     - 时钟中断周期递减当前进程剩余时间片（如 10ms）；
     - 当时间片为 0 时，调用 `yield()` 将当前进程放入就绪队列尾部，调度队列头部新进程执行。
   - **进阶加分：多级反馈队列（MLFQ）**：
     - 设置 3 个不同优先级的就绪队列（Q0 高优先/时间片 5ms，Q1 中优先/10ms，Q2 低优先/20ms）；
     - CPU 密集型任务自动降级至低优先级队列，I/O 密集型或新唤醒任务保留在高优先级，兼顾交互响应与吞吐量。

---

### 3.3 并发、同步与银行仿真子系统（Synchronization Architecture）
1. **同步互斥原语分层**：
   - **自旋锁（`SpinLock`）**：
     - 底层采用原子指令 `amoswap.w.aqrl`（RISC-V）或 `lock cmpxchg`（x86），结合 RAII 类 `SpinLockGuard` 保证异常退出自动解锁。
   - **睡眠互斥锁（`Mutex`）与信号量（`Semaphore` - P-V 原语）**：
     - 维护一个内部阻塞等待队列（`WaitQueue`）；
     - 当信号量计数器 $\le 0$ 时，调用 `P()` 操作将当前进程状态置为 `Blocked` 并让出 CPU；
     - 当其他进程调用 `V()` 操作时，唤醒队列中的等待进程并加入就绪队列。
2. **经典银行存取款业务并发仿真架构**：
   - **模型设计**：
     ```cpp
     class BankAccount {
     private:
         int64_t balance;
         Semaphore sem{1}; // 互斥信号量 (初始值=1)
     public:
         void deposit_unsafe(int64_t amount);  // 无锁竞争版本 (用于对比复现BUG)
         void withdraw_unsafe(int64_t amount);
         void deposit_safe(int64_t amount);    // P-V 保护版本 (保证ACID原子性)
         void withdraw_safe(int64_t amount);
     };
     ```
   - **测试架构**：创建 10 个并发线程，各执行 1,000 次存取款。在无锁状态下必然因时钟中断打断引起“丢失修改”，账目出现严重差额；启用 P-V 保护后，账目 100% 保持精准平衡，在答辩中具备极强视觉冲击力。

### 3.4 虚拟文件系统 (VFS) 与 ELF 加载架构
1. **抽象 VFS 层次**：
   - 定义标准的面向对象接口：`VNode`, `FileSystem`, `FileDescriptor`。
   - 实现两个后端文件系统：
     - **RamFS / InitFS**：静态内存只读文件系统，直接将编译期打包的外部二进制文件嵌入内核只读段，开箱即用。
     - **FAT32 驱动**：解析引导扇区（BPB）、FAT 表与目录项（Directory Entries），支持外部虚拟磁盘镜像读写。
2. **ELF64 加载器引擎（`ElfLoader`）**：
   - 读取 ELF Magic Header（`\x7fELF`），校验目标架构为 `EM_X86_64`；
   - 遍历 `Program Header` 表，筛选类型为 `PT_LOAD` 的段；
   - 根据段的 `p_vaddr`、`p_memsz`、`p_filesz` 在进程的 `MemorySet` 中分配物理页并建立映射；
   - 将二进制代码/数据从文件精确拷贝至映射物理页，若 `p_memsz > p_filesz`，则将剩余 BSS 区域清零；
   - 解析出 `e_entry` 入口地址，写入用户进程 `TrapContext.rip`，完成加载。

## 4. 高端加分项详细架构（主打 GUI 2D 桌面引擎）

### 4.1 【核心主打加分项】GUI 图形渲染与桌面交互引擎
- **设备抽象与 VBE/Bochs 显存映射**：
  - 在 MBR 引导或内核阶段通过 VBE (VESA BIOS Extensions) 模式或 Bochs VBE 显卡寄存器（I/O 端口 `0x1CE/0x1CF`）将显卡切换至高分辨率真彩色图形模式（如 `1024x768x32bpp` 或 `800x600x32bpp`）；
  - 将显存线性地址（Linear FrameBuffer，通常位于物理高区如 `0xE0000000` 或 `0xFD000000`）映射至内核高地址虚拟空间，获取连续 32 位 ARGB（`0xAARRGGBB`）直接显存写入指针。
- **高性能双缓冲无闪烁渲染管线**：
  ```
  [桌面控件 / 性能监视器 / 窗口] ──> [2D Painter 绘图引擎 (点/线/矩形/字库)]
                                                 │
                                                 ▼
                                [Back Buffer 堆内渲染双缓冲区]
                                                 │ (脏矩形 Blit / memcpy 批量搬运)
                                                 ▼
                                [Front Framebuffer 硬件显存]
  ```
- **核心 2D 图形引擎能力**：
  1. **画点与清屏**：支持 `draw_pixel(x, y, color)` 与 `clear_screen(color)`；
  2. **线段光栅化**：基于经典整数 Bresenham 算法实现任意斜率的抗锯齿线段绘制；
  3. **矩形与边框渲染**：支持纯色实心矩形填充、圆角矩形与带阴影渐变边框；
  4. **文字排版引擎**：内嵌标准 8x16 ASCII 点阵字库，支持在任意屏幕坐标以指定前景色/背景色打印文字串；
  5. **动态性能监视器桌面 Demo**：
     - 在屏幕顶端渲染半透明磨砂风格状态栏（展示 SimpleOS Logo、运行时间 Uptime、CPU 当前时钟与内存水位百分比）；
     - 绘制可交互的主窗口，以动态折线波形图（波形滚动刷新）实时绘制系统调度线程的 CPU 负载波动。

### 4.2 【待选备选加分项】Security 安全防护架构
- **CR0/CR4 与硬件页表隔离**：
  - 开启 `CR0.WP`（写保护位，禁止内核态意外写入只读用户代码页）；
  - 配置页表条目 `U/S` 位，Ring 3 用户态代码试图访问内核地址空间立即由 CPU 硬件抛出 14 号 Page Fault 异常，内核直接终结非法进程。
- **安全的内核数据搬运（Safe Copy Engine）**：
  ```cpp
  bool copy_from_user(void* kdst, const void* usrc, size_t len);
  bool copy_to_user(void* udst, const void* ksrc, size_t len);
  ```
  在系统调用读取用户指针前，检查 `usrc + len` 是否落在合法 Canonical 用户空间内，杜绝通过野指针破坏内核空间。

### 4.3 【待选备选加分项】Parallel 对称多核处理 (SMP) 架构
- **x86 多核引导流程**：
  1. BSP（Bootstrap Processor，主核 Core 0）执行初始引导并配置好物理内存、GDT 与初始页表；
  2. BSP 通过 Local APIC 发送 INIT-SIPI-SIPI（初始化与启动核间中断）广播序列唤醒 AP（Application Processors，从核 Core 1~N）；
  3. AP 启动汇编加载独立的 64 位长模式环境、配置独立的内核私有栈并向 BSP 发送同步就绪信号；
- **并发控制**：
  - 定义 `PerCpu` 结构，通过 `GS/FS` 段基地址寄存器寻址当前核心私有数据；
  - 调度队列受自旋锁（`lock cmpxchg`）严格保护。

### 4.4 【待选备选加分项】Distributed / Network 网络子系统架构
- **VirtIO-Net 驱动**：在 QEMU 中挂载虚拟网卡，配置 PCI/MMIO 描述符环 Virtqueue。

### 5.2 现代 C++ 裸机基础设施实现规范
```cpp
// 禁用标准库，在 kernel 命名空间内重载 new / delete
void* operator new(size_t size) {
    return mm::kmalloc(size);
}

void operator delete(void* ptr) noexcept {
    mm::kfree(ptr);
}

// 支持 Placement New 原语
inline void* operator new(size_t, void* ptr) noexcept {
    return ptr;
}
```
通过上述标准基础设施，SimpleOS 彻底告别传统 C 语言大量 void* 强转和手动内存管理的混乱局面，具备无与伦比的代码工程质量与答辩表现力。
