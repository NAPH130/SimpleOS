# 最小内核启动说明

## 本阶段的目标

在 QEMU 模拟的 x86_64 计算机上，通过 Limine 加载 C++ 内核，并在模拟串口显示 SimpleOS 字符画与启动日志。项目还没有用户态、调度器或内存分配器。

## 从源码到输出

1. `make build` 编译 `Makefile` 的 `SOURCES` 和 `ASM_SOURCES` 中列出的内核文件。内核采用 freestanding C++17 编译，异常入口用汇编实现。
2. 链接器根据 `linker.ld` 合并目标文件，生成 `build/kernel.elf`。脚本指定入口 `kernel_main`、内核虚拟地址，以及各段的读写执行权限。
3. 构建过程下载固定提交的 Limine v10.8.5，将引导器、`src/boot/limine.conf` 和内核放入 BIOS 可启动 ISO。
4. QEMU 的 BIOS 从 ISO 启动 Limine；Limine 根据配置加载 ELF 内核，准备协议规定的 64 位执行环境，然后跳至 `kernel_main`。
5. 内核初始化 COM1 串口并打印 SimpleOS 字符画，随后用 `kprintf_log` 输出串口初始化和引导协议检查结果。串口驱动通过 x86 I/O 端口写入字符，QEMU 将输出显示到终端。
6. 内核保持可屏蔽中断关闭，加载 IDT，执行 `int3` 自检并从异常处理返回，最后执行 `hlt`。用 `Ctrl+C` 结束 QEMU。

## 关键概念

- **BIOS 和引导器**：BIOS 是模拟计算机开机时运行的固件；Limine 是负责加载内核的引导程序。当前 ISO 中的 BIOS 引导代码由 Limine 提供，我们没有自行编写 MBR。
- **引导协议**：内核中的请求标记和 base revision 表示使用 Limine 协议。内核检查引导器是否接受指定版本；不支持时会通过串口输出错误信息。
- **ELF 与链接脚本**：ELF 是内核文件格式；链接脚本指定入口、段位置和权限。这里的高地址是内核使用的虚拟地址，不代表内核必须位于同样高的物理地址。
- **初始环境**：在内核入口处，Limine 已设置初始栈和分页环境。以后实现自己的内存管理时仍需要理解和替换相关机制。
- **串口**：`src/drivers/serial.cpp` 通过 COM1 的 I/O 端口初始化和输出。QEMU 的 `-serial stdio` 将模拟串口连接到当前终端，并不依赖 Windows 或 Linux 的 `printf`。

## 运行与验证

在 WSL 的项目根目录中执行 `make run`，终端先显示 SimpleOS 字符画，随后显示以下日志。

```text
[INFO] COM1 serial console initialized.
[INFO] Limine base revision accepted.
[DEBUG] before int3
[DEBUG] breakpoint handled
[DEBUG] after int3
[INFO] Minimal kernel ready. Halting CPU.
```

使用 `make test` 可自动启动 QEMU，检查字符画、日志顺序和 `int3` 是否返回。内核会停机等待，因此测试脚本在 15 秒后停止模拟器，再检查输出。构建依赖和详细命令见项目根目录的 README。

## 断点异常路径

`int3` 的执行流程和各条日志的含义见 [Trap 功能介绍](Trap功能介绍.md)。

| 文件 | 职责 |
| --- | --- |
| `src/arch/x86_64/idt.cpp` | 用当前内核代码段注册第 3 号向量并加载 IDT。 |
| `src/arch/x86_64/trap_entry.S` | 补齐向量号和错误码，保存通用寄存器，调用 C++，恢复现场并用 `iretq` 返回。 |
| `include/arch/x86_64/trap.hpp` | 定义汇编和 C++ 共用的 `TrapFrame` 栈布局。 |
| `src/arch/x86_64/trap.cpp` | 根据向量分发事件，当前处理 `int3` 触发的断点异常。 |

`TrapFrame` 的尾部由 CPU 压入，汇编在传入 C++ 前对齐调用栈并清除方向标志。当前只注册第 3 号向量，整个自检期间保持可屏蔽中断关闭。 [Intel 系统编程手册](https://www.intel.com/content/www/us/en/developer/articles/technical/intel-sdm.html) · [AMD64 System V ABI](https://gitlab.com/x86-psABIs/x86-64-ABI/-/blob/master/x86-64-ABI/low-level-sys-info.tex)

## 内核格式化输出

`include/kernel/console.hpp` 声明 `kprintf`，`src/kernel/console.cpp` 实现格式解析并调用串口驱动。调用前必须初始化串口。支持 `%s`、`%c`、`%d`、`%i`、`%u`、`%x`、`%X`、`%p` 和 `%%`，例如：

```cpp
kprintf("task %u: %s (%x)\n", 3u, "ready", 0x2au);
```

`%d` 和 `%i` 接受 `int`，`%u`、`%x` 和 `%X` 接受 `unsigned int`，`%c` 接受提升后的 `int`，`%s` 接受字符串指针，`%p` 接受 `void*`（调用时显式转换）。空字符串指针显示为 `(null)`，空指针显示为 `0x0`。不支持宽度、精度、长度修饰符或浮点数；未识别的 `%` 加单个字符会原样输出，末尾单独的 `%` 也会保留。该接口不返回字符数，暂不保证并发或中断重入时的输出完整性。

`kprintf_log` 的首个参数是 `LogLevel`，后面的格式字符串和参数与 `kprintf` 相同。

```cpp
kprintf_log(LogLevel::DEBUG, "Trap vector %u\n", 3u);
kprintf_log(LogLevel::INFO, "Task %u is ready\n", 3u);
kprintf_log(LogLevel::WARN, "Queue nearly full\n");
kprintf_log(LogLevel::ERROR, "Failed to initialize %s\n", "timer");
```

在支持 ANSI 颜色的终端中，`[DEBUG]`、`[INFO]`、`[WARN]`、`[ERROR]` 方括号内的文字分别显示为蓝色、绿色、黄色、红色，正文使用默认颜色。每条消息的换行由格式字符串中的 `\n` 指定。

`make test` 在宿主机上检查格式化输出和日志颜色序列，并在 QEMU 中检查内核的串口输出。
