# 最小内核启动说明

## 本阶段的目标

在 QEMU 模拟的 x86_64 计算机上，通过 Limine 加载 C++ 内核，并将 `[SimpleOS] Hello, kernel!` 输出到模拟串口。项目还没有用户态、调度器或内存分配器。

## 从源码到输出

1. `make build` 编译 `Makefile` 的 `SOURCES` 中列出的引导协议、内核入口、控制台和串口驱动。内核采用 freestanding C++17 编译，禁用异常和 RTTI。
2. 链接器根据 `linker.ld` 合并目标文件，生成 `build/kernel.elf`。脚本指定入口 `kernel_main`、内核虚拟地址，以及各段的读写执行权限。
3. 构建过程下载固定提交的 Limine v10.8.5，将引导器、`src/boot/limine.conf` 和内核放入 BIOS 可启动 ISO。
4. QEMU 的 BIOS 从 ISO 启动 Limine；Limine 根据配置加载 ELF 内核，准备协议规定的 64 位执行环境，然后跳至 `kernel_main`。
5. 内核初始化 COM1 串口，借助 `src/boot/limine.cpp` 检查协议版本，再调用 `kprintf` 格式化启动消息。串口驱动通过 x86 I/O 端口写入字符，QEMU 将输出显示到终端。
6. 当前内核没有中断处理器和调度器，打印后禁用中断并执行 `hlt`，保持停止状态；用 `Ctrl+C` 结束 QEMU。

## 关键概念

- **BIOS 和引导器**：BIOS 是模拟计算机开机时运行的固件；Limine 是负责加载内核的引导程序。当前 ISO 中的 BIOS 引导代码由 Limine 提供，我们没有自行编写 MBR。
- **引导协议**：内核中的请求标记和 base revision 表示使用 Limine 协议。内核检查引导器是否接受指定版本；不支持时会通过串口输出错误信息。
- **ELF 与链接脚本**：ELF 是内核文件格式；链接脚本指定入口、段位置和权限。这里的高地址是内核使用的虚拟地址，不代表内核必须位于同样高的物理地址。
- **初始环境**：在内核入口处，Limine 已设置初始栈和分页环境。以后实现自己的内存管理时仍需要理解和替换相关机制。
- **串口**：`src/drivers/serial.cpp` 通过 COM1 的 I/O 端口初始化和输出。QEMU 的 `-serial stdio` 将模拟串口连接到当前终端，并不依赖 Windows 或 Linux 的 `printf`。

## 运行与验证

在 WSL 的项目根目录中执行 `make run`，应看到：

```text
[SimpleOS] Hello, kernel!
```

使用 `make test` 可自动启动 QEMU，检查串口输出。内核会停机等待，因此测试脚本在 15 秒后停止模拟器，再检查输出。构建依赖和详细命令见项目根目录的 README。

## 内核格式化输出

`include/kernel/console.hpp` 声明 `kprintf`，`src/kernel/console.cpp` 实现格式解析并调用串口驱动。调用前必须初始化串口。支持 `%s`、`%c`、`%d`、`%i`、`%u`、`%x`、`%X`、`%p` 和 `%%`，例如：

```cpp
kprintf("task %u: %s (%x)\n", 3u, "ready", 0x2au);
```

`%d` 和 `%i` 接受 `int`，`%u`、`%x` 和 `%X` 接受 `unsigned int`，`%c` 接受提升后的 `int`，`%s` 接受字符串指针，`%p` 接受 `void*`（调用时显式转换）。空字符串指针显示为 `(null)`，空指针显示为 `0x0`。不支持宽度、精度、长度修饰符或浮点数；未识别的 `%` 加单个字符会原样输出，末尾单独的 `%` 也会保留。该接口不返回字符数，暂不保证并发或中断重入时的输出完整性。

`make test` 还会运行宿主机上的格式测试，覆盖整数边界、指针和不支持的格式；QEMU 测试则验证实际内核通过串口输出。
