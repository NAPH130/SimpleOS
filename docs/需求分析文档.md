# SimpleOS 需求分析文档 (完整版)

---

## 1. 项目背景与设计目标

### 1.1 背景与现状调研
在操作系统教学实践中，参考材料（如基于 Rust/RISC-V 的 `GardenerOS` / `rCore-Tutorial-v3` 系列）通常将各个核心实验拆分为独立的章节性 Demo。这种模式割裂了操作系统各子系统（CPU上下文、内存管理、调度器、同步原语、文件系统）之间的强耦合与协作关系，无法使学生建立完整的“全景式操作系统工程认知”。

本项目 **SimpleOS** 旨在突破“实验代码孤岛”的局限，并结合本地开发环境与课程大纲要求：
1. **统一连续性**：采用统一工程架构，代码随实验阶梯式增量演进，最终形成一个可独立在裸机（或 QEMU 模拟器）上完整启动并运行多任务、文件系统、交互式 Shell 及图形界面的现代单体操作系统。
2. **纯现代 C++（Freestanding C++17/20）实现**：使用无宿主环境（Freestanding）的 C++ 面向对象与现代抽象机制（封装、RAII、模板、强类型枚举、运算符重载），大幅提升内核代码的健壮性、可读性与模块化设计水准。
3. **基于当前宿主 CPU 架构 (x86_64)**：精准对齐宿主机硬件平台（AMD Ryzen 7 9700X / x86_64 体系），完全契合课程大纲与截图中明确要求的 **`Bootloader (MBR)`** 规范，原生利用主机 `gcc/g++` 编译构建，省去繁重的跨平台交叉编译器配置，同时支持 QEMU KVM 硬件直通加速。
4. **主打 GUI 图形加分项，兼顾多元扩展**：以 **GUI 图形子系统（VBE / Framebuffer 2D 桌面引擎）** 作为核心主打高端加分项，并在架构上保留 SMP 多核、安全隔离与网络栈作为备选扩展。

## 3. 六大核心阶段业务需求分析

### 3.1 阶段一：环境搭建与最小化内核（对应实验 0, 1, 2 合并）
- **FR-1.1 开发与交叉编译环境**：
  - 基于 Linux (Ubuntu / WSL2)，构建 `riscv64-unknown-elf-gcc/g++` 或 `x86_64-elf-gcc/g++` 编译工具链与 GDB 调试环境。
  - 编写多层解耦的 `Makefile` 或 `CMakeLists.txt`，支持一键式构建内核镜像与启动 QEMU。
- **FR-1.2 裸机引导与启动环境**：
  - 规范内存物理布局（通过链接脚本 `linker.ld`），将内核加载至约定基地址（如 RISC-V 的 `0x80200000`）。
  - 实现汇编启动入口 `_start`，清空 `.bss` 段，初始化内核启动栈指针（SP）。
- **FR-1.3 基础 I/O 与格式化输出**：
  - 封装底层 UART 串口驱动或 SBI 控制台字符打印接口。
  - 在无 C 标准库支持下，纯手工自研 `kprintf`，支持 `%d, %u, %x, %p, %s, %c` 格式化打印及彩色日志级别（DEBUG, INFO, WARN, ERROR, PANIC）。

### 3.2 阶段二：特权级管理、异常中断与系统调用
- **FR-2.1 特权级与执行环境隔离**：
  - 严格区分内核态（Supervisor Mode / Ring 0）与用户态（User Mode / Ring 3）。
  - 内核启动后能够构造初始用户上下文，安全降权切换至用户态程序执行。
- **FR-2.2 中断与异常分发机制 (Trap)**：
  - 编写底层通用陷阱处理入口 `trap_entry.S`，在内核栈上完整保存/恢复所有通用寄存器（TrapFrame/Context）。
  - 实现 C++ 异常分发器：区分系统调用（ECALL / INT 0x80）、外部设备中断、时钟中断与硬件错误异常（Illegal Instruction, Page Fault 等）。
- **FR-2.3 系统调用核心链路**：
  - 定义系统调用规范与调用号（与标准 Linux 尽量靠拢），传参遵循 ABI 规范。
  - 提供至少两个基础系统调用：`sys_write`（用户态输出字符/字符串）和 `sys_exit`（用户态程序退出）。
  - 编写用户态基础运行时库（`libuser`），封装 `ecall` / `int` 汇编指令，供独立用户程序调用。

### 3.3 阶段三：内存管理（从连续分区到分页隔离）
- **FR-3.1 内存空间划分**：
  - 将物理内存划分为内核保留区（Kernel Space）与用户可用空间（User Space）。
  - 记录物理内存探测信息，获取物理 RAM 起始与终止范围。
- **FR-3.2 动态分区与堆内存分配 (Variable Partitioning / Heap)**：
  - **基线需求**：实现动态分区分配（首次适应 First-Fit 或最佳适应 Best-Fit），支持内核级动态内存分配。
  - **进阶加分需求**：构建 Buddy System（伙伴系统）页级分配器 + Slab/Object Cache 细粒度对象分配器，重载 C++ `operator new` 与 `operator delete`。
- **FR-3.3 用户空间加载与隔离**：
  - 将外部独立编译的用户程序二进制镜像拷贝至指定的用户内存空间。
  - 进阶实现：基于硬件 MMU（如 RISC-V SV39 或 x86 4级分页），为每个用户程序建立独立的二级/三级页表，完成内核虚拟空间与用户私有虚拟空间的强硬隔离与保护。

### 3.4 阶段四：多任务机制与调度算法
- **FR-4.1 任务控制块 (PCB/TCB) 与生命周期管理**：
  - 设计进程/线程控制块：包含 PID、任务状态（Uninitialized, Ready, Running, Blocked, Zombie）、内核栈、上下文指针、执行统计等。
  - 实现进程状态机转换流转机制。
- **FR-4.2 上下文切换核心机制**：
  - 编写无副作用的高性能汇编切换函数 `__switch(current_ctx, next_ctx)`，精准保存 Callee-Saved 寄存器与栈指针。
- **FR-4.3 协作式调度 (Cooperative Multitasking)**：
  - 提供 `sys_yield` 系统调用，允许用户进程在空闲或等待时主动让出 CPU 使用权。
- **FR-4.4 抢占式调度 (Preemptive Multitasking)**：
  - 配置可编程定时器与时钟中断（RISC-V `sbi_set_timer` / `mtimecmp`，或 x86 PIT/APIC Timer）。
  - 时钟中断周期性递减当前进程时间片，时间片耗尽后强制触发调度器重新选路（Round-Robin 时间片轮转）。
  - **进阶加分**：实现多级反馈队列（MLFQ）算法，动态根据进程 CPU/IO 行为调整优先级。

### 3.5 阶段五：同步互斥与经典并发场景仿真
- **FR-5.1 同步与互斥原语实现**：
  - 实现关中断锁（CriticalSectionGuard，单核环境基本互斥保护）。
  - 实现基于硬件原子指令（`amoswap` / `lr.w-sc.w` / `lock cmpxchg`）的自旋锁（SpinLock）。
  - 实现带阻塞等待队列的睡眠互斥锁（Mutex）与计数信号量（Semaphore，P-V 原语）。
- **FR-5.2 经典并发业务仿真（银行存取款业务）**：
  - 按照实验要求设计模拟银行账户模型（Account），包含全局账户余额字段。
  - 创建多个并发执行的线程/用户任务，高频发起存款与取款操作。
  - **对比演示**：
    1. *未加锁场景*：因竞态条件（Race Condition）导致数据竞争，最终余额账目错乱，直观暴露并发隐患。
    2. *P-V 锁保护场景*：利用 Semaphore / Mutex 对账户操作加锁，实现严格的临界区互斥，保证最终账目绝对一致。
  - **进阶拓展**：仿真多账户转账死锁场景，并演示“资源按序分配法”与“银行家算法”成功预防/避免死锁。

### 3.6 阶段六：文件系统与 ELF 二进制加载
- **FR-6.1 文件格式与元数据解析**：
  - 实现标准 ELF（Executable and Linkable Format）64位文件头与程序头（Program Header）解析器。
  - 读取 ELF Magic Number、入口地址（Entry Point）、段加载虚拟地址（VAddr）、文件偏移（Offset）与内存权限标识（R/W/X），按需加载代码段与数据段并清零 BSS。
- **FR-6.2 存储与文件系统组织**：
  - **基线需求**：实现静态只读 ramfs（或编译期打包的 CPIO/TAR 格式），能够列出目录文件清单、大小、权限等元数据。
  - **进阶/高端加分**：支持通用 VFS 抽象层，并实现只读/读写 FAT32 文件系统或 Ext2 精简驱动，支持通过扇区 I/O 驱动直接读取磁盘镜像内的文件。

## 4. 高端加分项（GSP/D 模型）深度需求分析

为了确保课程实验获得最高评级（高端加分 6 分满分），SimpleOS 特别规划 GSP/D 体系与交互式生态：

### 4.1 G (GUI) 图形用户界面子系统
- **G-1 帧缓冲（Framebuffer）抽象**：配置 QEMU `-device virtio-gpu-device` 或 `-vga std`，映射显存物理地址。
- **G-2 基础 2D 图形绘制库**：提供画点、线段（Bresenham算法）、填充矩形、圆形渲染能力。
- **G-3 字符与字体渲染**：内置 8x16 ASCII 点阵字库，支持在屏幕任意坐标渲染彩色文本。
- **G-4 动态桌面与控件演示 Demo**：
  - 实现双缓冲机制，杜绝屏幕闪烁。
  - 绘制包含状态栏（CPU 占用率、运行时间）、任务列表与动态图形波形图（如正弦波模拟性能监视器）的微桌面。

### 4.2 S (Security) 内核安全防护子系统
- **S-1 内存边界强隔离**：开启页表用户/内核特权级检查（U 标志位），用户态试图访问内核地址空间（0xFFFFFF...）将立即触发 Page Fault 并被内核强制终结，杜绝提权漏洞。
- **S-2 系统调用安全性检查（Safe Copy）**：
  - 实现 `copy_from_user` 与 `copy_to_user`。
  - 严格校验用户传入指针是否在用户虚拟空间范围内，杜绝用户态通过恶意系统调用指针污染内核空间。
- **S-3 栈金丝雀与栈越界保护**：在内核栈底设置 Canary 哨兵值，每次上下文切换检测栈溢出。

### 4.3 P (Parallel) 对称多核处理 (SMP)
- **P-1 多核初始化与唤醒**：主核（Boot Core）启动并初始化基本环境后，通过 SBI HSM（Heartbeat / Core Boot）或 APIC 发送 IPI 唤醒从核（Application Processors）。
- **P-2 Per-CPU 数据结构**：为每个 CPU 核心分配独立的内核栈、当前运行进程指针与本地调度器。
- **P-3 大内核锁（BKL）到细粒度调度自旋锁演进**：确保在多核并发时，调度就绪队列与全局资源的原子性。

### 4.4 D (Distributed / Network) 网络子系统
- **D-1 虚拟网卡驱动**：编写 VirtIO-Net PCI/MMIO 驱动，建立收发描述符环（Virtqueue）。
- **D-2 极简以太网与网络协议栈**：
  - 解析以太网帧（Ethernet Frame），处理 ARP 请求与响应。
  - 实现 IPv4 校验和计算与 ICMP 协议解析。
  - 外部宿主机通过 `ping 192.168.x.x` 时，SimpleOS 内核能正常产生 Echo Reply 并成功响应回显。

### 4.5 交互式终端与 Shell 生态
- 编写用户态 `sh`（Shell）程序，通过标准输入（UART 键盘）接收用户命令：
  - `help`：列出所有支持指令
  - `ps`：显示当前系统中所有进程的状态、PID、内存占用
  - `ls / cat`：浏览文件系统目录与查看文件内容
  - `bank_demo`：一键触发 P-V 银行存取款并发测试（可视化输出竞态 vs 加锁结果）
  - `gui`：切换进入图形界面演示
  - `reboot / halt`：安全关机或重启

## 5. 非功能性需求与工程约束

1. **Freestanding 约束**：不引用任何 Linux 宿主操作系统头文件（禁止 `#include <iostream>`, `#include <vector>` 等），全套容器、字符串工具均自建。
2. **现代 C++ 规范**：使用 C++17 或 C++20，启用 `-std=c++17 -Wall -Wextra -fno-builtin -fno-exceptions -fno-rtti -nostdlib`。
3. **可解释性与文档完整度**：所有关键汇编与并发原语必须具备清晰的中文注释，支撑 3 分的“能说清楚”与 1 分的“抗干扰现场提问”。
4. **编译与运行自动化**：单个命令 `make run` 即可编译全量内核与用户程序并自动启动 QEMU 模拟器。
