# 07 - Phase 7：高端加分主打：GUI 图形引擎与监控桌面

## 1. 详细的具体工程开发实施计划

### 1.1 阶段目标与交付物
实现 **高端加分项（超出常规圈子，满分 6 分攻坚核心）**：驱动 VBE/Bochs 线性显存 Framebuffer，构建高性能双缓冲（Double Buffering）无闪烁 2D 绘图管线，内嵌点阵字库，并实现一个**具备动态性能波形走势监控的现代化图形桌面 Demo**。
- **交付源文件**：
  - `drivers/vbe.cpp` & `vbe.hpp`：VBE / Bochs 线性显存显卡配置驱动（1024×768×32bpp 真彩色）
  - `gui/canvas.cpp` & `canvas.hpp`：双缓冲（Back Buffer）内存画布管理与硬件显存快速 Blit
  - `gui/font8x16.hpp`：内嵌 8×16 ASCII 高清点阵字库
  - `gui/painter.cpp` & `painter.hpp`：2D 基础图形渲染引擎（画点、Bresenham 线段、矩形填充、文本排版）
  - `gui/desktop.cpp` & `desktop.hpp`：动态性能监控微桌面（包含深色状态栏、时钟、动态折线图窗口）

### 1.2 详细开发排期与子任务
1. **子任务 7.1：实现显卡驱动与线性显存物理映射 (`drivers/vbe.cpp`)**
   - 通过 I/O 端口 `0x1CE / 0x1CF` 访问 Bochs VBE 寄存器；
   - 设置显示模式：`INDEX_XRES = 1024`, `INDEX_YRES = 768`, `INDEX_BPP = 32`, `INDEX_ENABLE = 0x41`（开启线性 Framebuffer 与 VBE 模式）；
   - 获取显卡线性显存基地址（通常为 `0xE0000000` 或 `0xFD000000`），在内核页表中建立恒等/高端虚拟映射，获取可直接写入像素的指针 `uint32_t* front_fb`。
2. **子任务 7.2：构建双缓冲无闪烁渲染管线 (`gui/canvas.cpp`)**
   - 在内核堆中动态开辟后台缓冲区：
     $$\text{BufferSize} = 1024 \times 768 \times 4\text{ 字节} = 3,145,728\text{ 字节} \approx 3.14\text{MB}$$
   - 提供 `Canvas` 抽象类：所有上层绘图操作（画点、画线、画文字）全部在内存 `back_buffer` 中完成；
   - 实现 `present()` 函数：调用优化的 64 位整块内存快速拷贝指令，将 `back_buffer` 数据一次性刷新至 `front_fb` 硬件显存，彻底消除画面撕裂与屏幕闪烁。
3. **子任务 7.3：实现 2D 矢量与排版绘图库 (`gui/painter.cpp`)**
   - **基础画点**：`draw_pixel(x, y, color)`，处理屏幕边界剪裁（Clipping）；
   - **线段光栅化**：纯手写经典 Bresenham 线段算法，支持任意斜率线段绘制；
   - **矩形与边框**：实现实心填充矩形、半透明矩形（Alpha Blending）与阴影边框；
   - **文字渲染**：解析 8×16 点阵字库，将字模位（Bit）为 1 的像素渲染为前景色，为 0 的像素渲染为背景色或透明。
4. **子任务 7.4：开发动态性能监控桌面 Demo (`gui/desktop.cpp`)**
   - **深色磨砂质感顶栏**：
     - 左侧绘制 `SimpleOS Desktop v1.0` 徽标；
     - 右侧实时显示系统开机时间（`Uptime: 00:01:23`）与当前内存使用水位（`RAM: 14MB / 128MB`）；
   - **CPU 性能折线波形图窗口**：
     - 绘制带深灰背景与浅灰网格坐标轴的主窗口；
     - 维护历史 100 个时间点的 CPU 负载采样队列；
     - 每次刷新时将波形向左滚动一个像素，利用 Bresenham 线段平滑连接每个采样点，实时绘制出类似 Windows 任务管理器中的 CPU 负载动态波动曲线；
   - **时钟与任务列表小部件**：在右侧窗口列出当前系统中各任务的 PID、名称与执行状态。

## 3. 实现原理与方式

### 3.1 VBE / Bochs 线性显存直接写入原理
- **显存与颜色格式**：32bpp（Bits Per Pixel）使用 4 字节表示一个像素（`0x00RRGGBB`）。显存是一个连续的一维数组：
  $$\text{PixelOffset}(x, y) = y \times \text{Width} + x$$
  向 `front_fb[y * 1024 + x]` 写入数值 `0x00FF0000`，屏幕的 $(x, y)$ 坐标处将立即显示一个纯红色像素点。
- **Bochs VBE 端口协议**：
  - 向 I/O 端口 `0x1CE` 写入寄存器索引，向 `0x1CF` 读写数据；
  - 这种硬件接口被 QEMU、VirtualBox 与 Bochs 完全原生支持，不仅免去了在 16 位实模式下调用 BIOS 慢速中断的麻烦，而且能够在 64 位长模式下随时动态切换分辨率。

### 3.2 双缓冲（Double Buffering）消除闪烁的数学机理
- **屏幕撕裂原因**：显示器以固定频率（如 60Hz，约 16.6ms）从显存逐行扫描并发射电子束成像。若 CPU 在显存上直接进行复杂的清屏、逐像素画点，显示器会在绘制尚未完成的中间状态扫描该区域，人眼便会看到严重的画面闪烁与撕裂。
- **双缓冲解决方案**：CPU 在常规 RAM（后台缓冲区）中耗费若干毫秒完成全部复杂的几何计算与文字排版；绘制完毕后，使用 `memcpy` 或 64 位汇编批量传输指令，在极短微秒级时间内一次性覆写到前台显存，屏幕扫描始终只能捕捉到完整的一帧画面，从而达到专业级的丝滑视觉体验。

## 4. 实现工具与依赖

| 依赖项 | 作用说明 |
| :--- | :--- |
| **QEMU `-vga std`** | 启动参数，模拟标准 VBE 兼容显卡，提供 16MB 虚拟显存与线性映射端口 |
| **8×16 点阵字模数组** | 头文件 `gui/font8x16.hpp`，包含标准 ASCII 0~127 字符的 16 字节位图矩阵 |
| **Bresenham 整数算法** | 全程仅使用整数加法与位移运算，完全避免浮点运算，保证光栅化画线极致高性能 |
