# -> 讲解点：瞬间切换至 1024x768 高清真彩色显存，展示双缓冲渲染管线与 CPU 动态折线监控窗口！

### 3.2 随堂小提问（抗干扰 1 分）高频考点速记

1. **考点：为什么我们选择用 C++ 而不是像参考资料那样用 Rust 或纯 C？**
   - *答*：纯 C 缺乏封装与 RAII 资源管理，裸指针和手动释放锁极易造成死锁与野指针；而 Rust 在裸机实验下依赖大量 nightly 实验性语法与特定第三方 crate。我们采用 Freestanding C++17，不仅具备 C 语言贴合硬件的极致性能，还通过 RAII（`LockGuard`、`UniquePtr`）和面向对象模式，构建了模块高度解耦、架构极度清晰的一体化内核。
2. **考点：系统调用执行时，内核态和用户态是如何完成参数传递与隔离的？**
   - *答*：用户态将系统调用号存入 `rax`，三个参数存入 `rdi, rsi, rdx`，通过 `int 0x80` 陷落进入内核态。CPU 自动根据 TSS 切换至内核栈，汇编存根保存通用寄存器为 `TrapContext`。内核处理完毕后将返回值写入 `TrapContext.rax`，执行 `iretq` 原子降权恢复至用户态。
3. **考点：双缓冲技术具体是如何在数学上消除画面闪烁的？**
   - *答*：显示器以 60Hz 逐行扫描显存，直接在显存绘图会导致屏幕扫描到未绘制完的残缺半帧，产生闪烁。双缓冲在内存中开辟同等大小的 Back Buffer，CPU 在内存中完成全部复杂的光栅化画线和文字绘制后，通过 64 位宽总线 `memcpy` 在微秒内整体刷入显卡显存，显示器扫描到的始终是完整帧，彻底消除了画面撕裂。
