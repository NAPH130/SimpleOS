# 00 - 前置准备与开发环境搭建

---

## 1. 详细的具体工程开发实施计划

### 1.1 阶段目标与交付物
本步骤是 SimpleOS 开发的基石阶段，目标是在宿主机（x86_64 Ubuntu / WSL2）上构建一整套开箱即用的裸机系统开发、编译、链接与 QEMU 模拟调试环境。
- **目标产物**：
  - 宿主机交叉编译环境（汇编器 `nasm`、编译器 `g++`、链接器 `ld`、模拟器 `qemu-system-x86_64`）；
  - 自动化构建脚本验证工具链；
  - 源码目录规范与 Git 分支管理。

### 1.2 详细开发排期与子任务
1. **子任务 0.1：系统依赖包探测与一键安装**
   - 检查本地 Linux 发行版，更新软件源，安装必需的系统级裸机编译工具链。
2. **子任务 0.2：验证 GCC/G++ 对 Freestanding 模式的支持**
   - 编写一段最小的 C++ 代码，使用 `-ffreestanding -nostdlib` 编译测试，验证本地编译器支持现代 C++17 特性且脱离 C/C++ 标准库运行。
3. **子任务 0.3：验证 QEMU x86_64 仿真与虚拟硬件连通性**
   - 测试 QEMU 的终端输出、VGA 窗口重定向及 KVM 硬件加速支持情况。

## 2. 我（用户）需要干什么

### 2.1 依赖安装与执行命令
打开宿主机 Linux 终端（WSL2 / Ubuntu），执行以下命令安装工具链：

```bash
# 1. 更新 apt 软件源并安装基础编译与仿真依赖
sudo apt update
sudo apt install -y qemu-system-x86 nasm build-essential gdb xorriso qemu-utils

# 2. 验证各个关键工具链是否安装成功
nasm -v
g++ --version
qemu-system-x86_64 --version
```

### 2.2 验证结果判定
- 若 `nasm -v` 输出类似 `NASM version 2.15.xx`，`g++` 版本 $\ge 10.0$，且 `qemu-system-x86_64` 能够正常输出版本号，说明开发环境配置完毕。

## 3. 实现原理与方式

### 3.1 宿主机与目标机架构同构优势
- **原理**：当前宿主机 CPU 为 x86_64（AMD Ryzen 7 9700X），开发的目标操作系统 SimpleOS 同样基于 x86_64 架构。
- **方式**：无需配置复杂的跨架构交叉编译器（如 `riscv64-unknown-elf-gcc` 或 `aarch64-linux-gnu-gcc`），直接使用本地原生的 `g++` 与 `nasm`。编译速度极快，且 QEMU 可直接使用 `-enable-kvm` 开启硬件辅助虚拟化，以接近物理主机的性能执行内核代码。

### 3.2 独立运行环境（Freestanding Environment）机制
- **原理**：操作系统内核运行在裸机硬件之上，不存在底层的 Linux/glibc 提供系统调用（如 `malloc`、`printf`、`exit`）。
- **方式**：在编译选项中引入 `-ffreestanding` 与 `-nostdlib`，通知编译器不要链接任何标准库头文件与启动代码（`crt0.o`），所有运行时设施、内存分配与打印逻辑必须在内核源码中自行从零实现。

## 4. 实现工具与依赖

| 工具 / 依赖 | 版本要求 | 用途说明 |
| :--- | :--- | :--- |
| **NASM** | $\ge 2.15$ | x86_64 汇编器，负责将 16 位实模式、32 位保护模式和 64 位汇编代码编译为纯二进制镜像 |
| **GNU G++** | $\ge 11.0$ | 现代 C++ 编译器，编译内核的核心 C++ 类与算法，启用 `-std=c++17` |
| **GNU LD** | $\ge 2.35$ | 链接器，根据 `linker.ld` 链接脚本将各模块目标文件组织到约定的物理内存布局 |
| **QEMU x86_64**| $\ge 5.0$ | 硬件全系统模拟器，模拟 CPU、内存、VGA 显示卡、PIT 定时器、COM1 串口等外设 |
| **Make** | $\ge 4.0$ | 自动化工程构建工具，通过单个命令一键完成编译、打镜像与运行 |
